# MCA: Quests - Forge 1.20.1 Mod

## Orientation
Package layout and any registration inventory live in `MODMAP.md` (generated by
`.mcmod-tools/modmap.py`). Read that instead of crawling `src/`. Player-facing docs are
`README.md`, `CONFIG.md`, `DATAPACK.md`, `TOWNSTEAD.md`, `FTBQUESTS.md`, `ICEANDFIRE.md`, `BOUNTIFUL.md`, `CAPITALS.md`, `MAPATLASES.md`; `docs/` holds the specs.

## Quick Reference
- **Mod ID**: `mcaquests` - **Package**: `dev.otectus.mcaquests`
- **MC / Forge / mod version**: `gradle.properties`. Mappings `official`, Java 17 toolchain (build.gradle:27)
- **Network protocol version**: `QuestNetwork.PROTOCOL_VERSION` (network/QuestNetwork.java:57) - bump it whenever a packet's shape changes; client and server must match.

Version numbers live only in `gradle.properties`; `processResources` expands them into `mods.toml`
and `pack.mcmeta`. Never hard-code one elsewhere, this file included.

## Build
- `./gradlew compileJava` - the normal iteration loop
- `./gradlew test` - plain JUnit in `src/test/java`; no GameTest source set
- `./gradlew build` - also runs `verifyReobfJar` (build.gradle:673), which inspects actual Minecraft member references and rejects dev-mapped jars; `artifactVerifierTest` proves rejection
- `./gradlew installMod -PmodsDir=<dir>` - copies the verified jar into a mods folder (or `$MCAQUESTS_MODS_DIR`)
- `townsteadProbeTest` / `mapProbeTest` / `iceAndFireProbeTest` / `bountifulProbeTest` / `capitalsProbeTest` - replay a binding manifest against real third-party jars; need `-PtownsteadModernJar=` / `-PjourneymapJar=` / `-PiceandfireCeJar=` / `-PiceandfireOriginalJar=` / `-PbountifulJar=` / `-PcapitalsJar=` etc., so they are not part of `check`
- `McaBindingProbeTest` replays the MCA manifest against every build listed in `mca_probe_versions`, each in its own class loader
- Build annotation processor flag `-AMSG_MIXIN_SOFT_TARGET_NOT_FOUND=note` suppresses warnings about unreachable mixin targets in optional-mod jars
- `reliabilityRuntimeTestJar -PreliabilityRuntimeFixture=true` - builds the disposable production-server fixture in `tools/reliability-runtime-test/` (never shipped). Dev runs cannot load real MCA, so conversation, placement, repair and Townstead-track checks run on a production Forge server with it and `-Dmcaquests.rt.fixture=true`; `build/rt/row.sh` boots one row. The fixture also covers the 1.7.0 fixes (farming, held rewards, a vanished village, receipts, `/reload`); `-Dmcaquests.rt.phase=restart1..3` is a three-boot restart row over one world (escort leases, datapack drift, a Townstead outage)
- `townsteadRuntimeTestJar -PtownsteadRuntimeFixture=true` - the disposable Townstead bridge fixture from #1 (`tools/townstead-runtime-test/`, `-Dmcaquests.townstead.fixture=true`); it exercises whichever Townstead binding loads
- `ApiJarClosureTest` fails the build when an exported API signature names a type missing from `apiReadModel` (build.gradle)

## Structure
```
api/        public extension points for add-ons - changes here are source-breaking downstream
client/     screens, HUD, toasts, client-side mirrors of server state
command/    /mcaquests admin and debug commands
compat/     shared CompatProvider/CompatRegistry framework, pack/* conditional embedded datapacks, 
            reflective adapters plus isolated typed FTB, Reputation, Crime and JourneyMap packages, and
            mapatlases/ (with its own client/ subpackage) for the Map Atlases binding
data/       datapack loaders and validators (quests, tiers, titles, situations)
event/      Forge event handlers
mixin/      mcaquests.mixins.json (one common accessor, two client classes), compat/ for the Bountiful hook
            mixin (one class, required: false, plugin-gated), mapatlases/ for
            mcaquests.mapatlases.mixins.json (two classes, required: false, plugin-gated), and mca/ for
            mcaquests.mca.mixins.json (eight classes: two hooks, one variant per MCA package root)
network/    packets and the SimpleChannel
profession/ villager profession matching
project/    village Project domain model
quest/      quest domain model - definitions, offers, chains, turn-in, journal
state/      persisted player and world data
```
Conditional embedded datapacks (e.g., `iafce_quests`, `bountiful_core`) are stored in 
`src/main/resources/compatpacks/` and mounted via `AddPackFindersEvent`.

## Key Dependencies
- MCA Reborn - mandatory at runtime, never a compile dependency; `mca_dev_version` only picks what dev runs launch with
- MCA: Reputation - vendored compile-only API jar (`libs/api/mcareputation-<v>-api.jar`, pinned in `gradle/sibling-apis.properties`, checked by `verifySiblingApis` before `compileJava`); `-PmcaReputationApiPath=<jar>` or the older `-PmcaReputationClasses=<dir>` overrides it; optional at runtime.
- MCA: Crime - vendored compile-only API jar on the same terms (`-PmcaCrimeApiPath=<jar>`); `compat/crime/` is the only importer (`NoCrimeStaticLinkTest`), reached through `compat/CrimeBridge` after a `ModList` check; optional at runtime (1.7.1).
- FTB Quests stack - `compileOnly`, never shipped; set `enableFtbqInDev=true` to get it in dev runs
- MCA Capitals - optional; set `enableCapitalsInDev=true` to get it in dev runs
- Townstead - optional, `[0.7.5,0.9)`; 0.7.x binds reflectively, 0.8's `api.v1` through the typed adapter in `compat/townstead/v1/`, compiled against `api.v1` sources fetched at `townstead_api_commit` (gradle.properties)
- Ultima Kingdoms - optional, Forge only; resolved by reflection in `compat/KingdomIntegration` (kingdom lifecycles, faction standing, institutional commissions, map points); no Ultima type is linked

## Conventions
- This mod registers no blocks, items or entities, so there is no `DeferredRegister` anywhere. Almost all "registration" here is optional-mod binding, not Forge registries.
- `@Mod.EventBusSubscriber` with no `bus=` (FORGE) is the default; MOD bus appears only where mod setup needs it (client/QuestClientSetup.java:15). A few compat bridges register manually on `MinecraftForge.EVENT_BUS` to control class-load timing (compat/ftbq/FtbqEventBridge.java:31).
- No access transformer. Cross-mod access goes through reflection/MethodHandles instead.
- Config is `ForgeConfigSpec` in `McaQuestsConfig.java`, split into `COMMON_SPEC` (server-safe) and `CLIENT_SPEC`. Every key is documented in `CONFIG.md`.
- MCA, Townstead 0.7.x, Xaero, Ice & Fire, Bountiful, Capitals, Ultima Kingdoms and Map Atlases are resolved by name/registry behind compatibility gates; static-link tests enforce isolation. Typed compile-only adapters are deliberate exceptions: FTB Quests under `compat/ftbq/`, MCA: Reputation under `compat/reputation/`, JourneyMap under `compat/journeymap/`, and Townstead's `api.v1` under `compat/townstead/v1/` (bound only when Townstead ships `api.v1`; `NoTownsteadStaticLinkTest` allows `api.v1` there and nowhere else). FTB and Reputation are initialized only after their mod presence gates; JourneyMap discovers its plugin. None of these dependencies is bundled. The Bountiful and Map Atlases mixins are optional and plugin-gated.

- Mixins: four configs. `mcaquests.mixins.json` has one common class and two client classes (Plain SpongePowered Mixin, no MixinExtras). The common `PlayerListAccessor` is an `@Invoker` for vanilla `PlayerList#save`, used only by the completion-receipt durability fence to save one player; it injects nothing. Client: `MinecraftGlowMixin` HEAD-injects into `Minecraft#shouldEntityAppearGlowing` and is `cancellable = true`, overwriting the return value to force `true` for highlighted entities; `ScreenAccessor` is a field `@Accessor` exposing vanilla `Screen`'s widget lists, not a draw injector, so cancelling/overwriting a return value does not apply to it. `mcaquests.compat.mixins.json` is common with one class targeting Bountiful's `io.ejekta.bountiful.bounty.BountyData.tryCashIn`, marked `required: false` and plugin-gated by `compat/bountiful/BountifulMixinPlugin`. It observes the return value only and never cancels or mutates. `mcaquests.mapatlases.mixins.json` is client-only with two classes targeting Map Atlases' own `AbstractAtlasWidget` (fullscreen/minimap) and `AtlasInHandRenderer` (held item), marked `required: false` and plugin-gated by `compat/mapatlases/MapAtlasesMixinPlugin`, which verifies an exact, version-pinned bytecode shape before applying either one; both only inject additional drawing and never cancel or overwrite a return value. Other mods can inject into the same Bountiful and Map Atlases methods, and coexistence there is safe. `mcaquests.mca.mixins.json` is common, `required: false`, plugin-gated by `compat/mca/McaGiftMixinPlugin` (which applies only the variant whose MCA package root is present and verifies the target's exact descriptor), with two hooks in four root variants each: the Gift hook HEAD-injects `VillagerCommandHandler.handle(ServerPlayer,String)` and cancels only a gift that paid a quest delivery; the dialogue hook (1.7.0) observes `EntityCommandHandler.interactAt(...)` at RETURN and never cancels or mutates. All eight pass `this` as `Object`, so none links an MCA type.
- Common code must not import `net.minecraft.client`; exceptions: the client mixins `mixin/MinecraftGlowMixin.java`, `mixin/ScreenAccessor.java`, `mixin/mapatlases/AtlasDisplayMixin.java` and `mixin/mapatlases/AtlasInHandMixin.java`, and the seven classes under `compat/mapatlases/client/`, which is itself a client-only package.
- Commands: `/mcaquests` runs on the server command dispatcher (common), while `/mcaquestsclient` runs on the client dispatcher from `client/ClientCommands.java` when the player is in-game.

## Terminology
- Players are only ever shown **Reputation**. The same concept is called *standing* in places internally (state/VillageStanding.java, network/OpenStandingC2SPacket.java) - grep both words.
- *Situation* and *incident* (client/SituationToast.java, compat/IncidentSelector.java) are internal names for the same thing; neither word reaches the player.
- *Suspended* / *paused* both name the player-visible "Quest paused" state when a quest cannot proceed due to missing optional-mod content (CHANGELOG, config keys, quest/QuestManager.java). The state is recoverable; installing the mod brings the quest back.

## Family compatibility

MCA: Reputation, MCA: Quests, MCA: Crime, MCA: Conversations and MCA: Mob Compatibility are one family of
MCA Reborn add-ons, and Ultima Kingdoms consumes their APIs. The rules below hold in every repository;
the verified companion tuple per release is kept once, in `MCAReputation/docs/FAMILY_COMPATIBILITY.md`.

- **MCA Reborn is the only mandatory dependency** (`[7.6,8)`), bound by name across its four package
  roots. Architectury is never declared mandatory: MCA 7.7 dropped it and this code names no Architectury type.
- **Companion ranges carry a lower bound only** (`[x.y,)`). Forge enforces an optional range whenever
  the mod is present, and every companion binding already probes the other mod and degrades, so an
  upper bound would only ever refuse a launch. The one exception is Townstead, which is third-party
  and read-only for us: `[0.7.5,0.9)` by decision, so its 0.8 line (the one that adds `api.v1`) can
  launch beside us while the binding stubs whatever it cannot resolve.
- **Sibling APIs are consumed through vendored, hash-pinned compile-only jars** (`libs/api/`,
  `gradle/sibling-apis.properties`, `verifySiblingApis`), never a sibling checkout's class output, so a
  clean clone builds the integrations a release ships. Each sibling has one adapter package, loaded by
  name after `ModList.isLoaded`, and a static-link test keeps its types out of everything else.
- **One MCA probe fleet** in every `gradle.properties`: `7.6.20`, `7.6.26`, `7.7.0-beta.2`,
  `7.7.1-alpha.2`, `7.7.1-beta.1`, `7.7.1-beta.2` (all `+1.20.1`), replayed by the binding probe test.
- **MCA: Reputation's capability strings are drift-checked** by every consumer at startup, and the
  `1.21.1 Ports/` NeoForge trees mirror every change made here.
