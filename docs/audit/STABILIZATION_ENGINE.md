# Engine, state, projects, objectives and rewards stabilization

Date: 2026-09-06. Targets: Forge 1.20.1 and NeoForge 1.21.1. Existing Capitals work in the Forge checkout was preserved and its applicable engine behavior was ported alongside these fixes. Platform-specific codecs, events, item components, saved-data registries and player attachments remain native to each port.

## Review coverage

The review traced quest offers and acceptance, frozen templates and payouts, readiness and turn-in, abandon/failure/completion, objective event and polling progression, target resolution, shared situations, guidance/journal assembly, reputation/title effects, project sponsorship/scope/phase advancement, deferred rewards, player cloning and world/player persistence. Public constructors and extension hooks were checked where these changes cross them. Static scans covered unfinished markers and counter/collection arithmetic in the owned `quest`, `project`, `state`, `event` and `api` trees. Model/loader strictness, resources, full configuration coverage, packets/client UI, commands and optional adapters were reviewed with the other audit owners; this report does not substitute for their coverage.

Runtime game testing has not been performed by this agent. Automated tests exercise the detached model, inventory, clock, codec and save paths; server player lifecycle and optional-mod behavior still need the runtime checks below.

## Implemented corrections

- A complete quest turn-in reserves all consuming and transferring delivery objectives against one source snapshot and all shared destination capacities before any mutation. Repeated item rows cannot spend the same stack twice. Item/tag handovers preserve actual stack data, respect slot restrictions and stack limits, refuse stale plans, and recover source/destination contents from ordinary throwing container callbacks. Public single-objective delivery entry points remain available.
- Self-completion requires the held active instance and the authored self-complete mode. Readiness checks account for combined consuming deliveries. A completion claim is cleared if a reversible inventory commit fails.
- Definitively lost bound targets can trigger authored failure even while their objectives report unavailable. Vacant, never-bound Capitals roles remain paused. Already satisfied target objectives do not become blocked when their former targets later disappear. Situation deadline wrappers retain `fail_on_target_lost`.
- Cancellable death, placement, break, interaction, fishing, breeding and taming observers run at the late Forge event priority, reducing progression/failure caused by events another handler cancels. NeoForge observers retain the corresponding native bus APIs.
- Objective/shared contribution and elapsed counters clamp or saturate instead of wrapping. Project placement records positions so breaking and replacing the same block cannot repeatedly earn contribution. Completed event objectives stop collecting extra credit while a later phase is locked. Large weighted offer totals use long arithmetic while ordinary seeded choices retain their previous random call path.
- Player cloning deeply copies active objectives, offers and saved substate. Removing a tracked quest clears its stale tracking reference. Malformed active quests, world project/situation entries and unknown pending reward entries are isolated and their original compounds retained for recovery alongside valid siblings.
- Projects recheck unlock conditions after objectives are complete, require an actual eligible participant context, persist polling baselines, respect per-player event contribution caps and new-instance offer limits, and refresh all affected online project logs. Datapack phase/objective edits cannot index beyond saved progress or loaded phase lists. Scope changes quarantine existing instances without deleting their state.
- Project failure settings now execute: elapsed/time-of-day deadlines, required weather, explicit sponsor/target death, failure hearts/reputation, retry delay and permanent retry blocking. Terminal state is set before effects. Old live projects receive a fresh failure clock when first checked, preserving existing progress and payouts. Old failed saves without a retry marker stay terminal. Paused, disabled, missing-definition/dimension, stale-scope and missing-required-integration periods are excluded from deadline time. Already satisfied final work is protected from late failure.
- Linked projects are validated for missing/disabled targets and incompatible scopes; runtime seeding refuses a child with an identity belonging to another scope instead of creating an immediately quarantined instance.
- Pending phase rewards include their original project instance identity and frozen snapshot, preserving their village, sponsor and currency amount after a retry or reset. Missing definitions/reward rows/dimensions and malformed snapshots remain banked; one broken entry does not discard its siblings. Legacy entries without identity are paid only when their participating, distributed instance is unambiguous. Pending village effects use the original anchor dimension.
- Project hearts use sponsor/participant context and bank unloaded recipients. Spouse delivery chooses among spouses before distance ranking. Project command rewards honor their separate configuration switch. Shared reputation rewards use their actual recipient set and a distinct row/instance dedupe key; failure and abandon reputation now use their authored outcomes. Explicit zero or canceling legacy completion reputation stays zero. Journal globals reconcile canonical offline title grants; migration discovers communities that contain only a tier high-water record.
- Currency and XP multipliers no longer narrow overflowing long amounts into negative ints; the full legal nonnegative currency range can be rolled. XP grants stop at the remaining capacity of Minecraft's integer level/total fields, avoiding an overflowing addition that erases existing XP. Inverted hearts bounds respect the configured maximum. Banked hearts saturate without changing sign.
- Plain item and currency rewards have a shared per-player limit of 16 immediate stacks per game tick. The exact remaining quantity is retained as long counts in additive player `pending_items` data and inserted into available main-inventory capacity at the existing once-per-second cadence. Delivery uses at most 16 stacks and examines at most 16 item IDs per pass; round-robin examination prevents an absent mod from starving later items. Unavailable IDs remain owed until restored. Dead/removed players retain all debt until a live entity can receive it. The insertion path does not use creative mode's discard-on-full inventory fallback. Existing item/currency reward schemas contain plain registry items; handover stack metadata is preserved separately by the inventory transaction.

## Compatibility and migration discipline

Existing JSON field names and existing public constructors/accessors remain. New project clocks, retry markers, pending instance snapshots, placement markers and pending item amounts use additive NBT fields with absent-field behavior. Unknown recoverable world/player entries are retained, not rewritten into fabricated defaults. NeoForge keeps its registry-aware saved-data entry points, component serialization and attachment migration marker; its migration-empty check includes newly retained raw entries and pending item debt so legacy import cannot overwrite them.

`PendingReward` preserves its original five-argument constructor and original factory while adding the instance-aware factory. Objective extension interfaces gain only default behavior. Existing Capitals capability and pause semantics are carried through both ports. Strict datapack validation is intentionally more diagnostic for malformed content; already valid schemas retain their shape.

## Manual runtime verification still required

- Forge 1.20.1 with both supported MCA 7.6.x and 7.7.x families, and the corresponding NeoForge environment: server/client login, death/respawn with and without `keepInventory`, disconnect/reconnect, save/restart and datapack removal/restoration while payouts are owed.
- Two players contributing to the same project, waiting at an unlock, crossing dimensions while offline rewards are pending, sponsor transfer/death, retry and admin reset with an old pending payout, and client/HUD refresh after each transition.
- Container interactions with MCA inventory implementations and other inventory-altering mods; ordinary callback failure rollback is covered automatically. Arbitrary add-on callbacks that reject rollback or perform irreversible external effects cannot be made transactionally reversible by container snapshots.
- MCA, Capitals, Townstead and canonical Reputation bridge behavior for temporarily absent capabilities, target replacement, unloaded sponsors/residents, offline titles and project failure effects.
- Test large payouts and full creative/survival inventories in game. The ledger preserves owed counts, but Minecraft's eventual disk flush, external command/reward side effects and third-party failures after a partial effect cannot provide crash-proof distributed exactly-once delivery. Ambiguous legacy pending entries and deliberately corrupted raw entries may need administrator inspection rather than an unsafe guessed recipient.
